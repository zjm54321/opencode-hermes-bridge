# OpenCode Hermes Bridge 验证与测试现状

本文档记录 OpenCode Hermes Bridge 各模块的测试覆盖证据、自动化验证结果、跨语言集成验证边界以及尚未完成的真实环境联调项。

- 适用项目：[OpenCode Hermes Bridge](https://github.com/zjm54321/opencode-hermes-bridge)
- 许可协议：GPL-3.0-or-later

---

## 1. 验证体系与分层边界

为了确保系统在网络不稳定、进程重启、恶意载荷及大文件传输下的健壮性，验证体系划分为六个层次：

1. **TypeScript 插件与客户端单元测试**：验证本地 Outbox 即时写入、配额前置校验、安全文件读取、轮询与退避机制、会话隔离及资源释放。
2. **Python Companion 服务端单元测试**：验证 HTTP 鉴权、单 Worker 串行执行、SQLite 崩溃恢复、幂等指纹计算、路径安全限制、显式路由合法性及凭证脱敏。
3. **跨语言端到端集成测试**：在本地真实 HTTP 协议栈下运行 TypeScript 核心客户端与 Python Companion 服务端，基于回显执行器（EchoRunner）验证多格式字节传输与生命周期完整性。
4. **同镜像容器 PID 1 守护与生命周期验收**：在同镜像独立隔离 Pod 中验证真实 PID 1 守卫、孤儿进程回收、阶梯超时强杀及平滑终止删除。
5. **生产环境 GitOps 部署与运行时安全验收**：验证 GitOps 发布状态、ACL 与 NetworkPolicy 双层约束、Pod 真实 UID/GID/CapEff、卷根目录与子目录 0700 私有收紧及固定鉴权探测。
6. **真实外部实体与模型联调**：验证真实模型调用与文件运输，严格区分历史默认链路最小联调（纯文本与夹具运输 PASS、视觉 INCONCLUSIVE）、显式模型路由短文本实机调用（PASS），以及未运行的宿主全链路 UI 回投。

> **重要边界声明**：
> - 自动化跨语言测试采用标准回显桩（EchoRunner）测试真实网络与文件字节流动，**不等于真实 Hermes 模型的语义理解**。
> - 真实宿主加载验证证明了插件在宿主内的**加载激活、工具注册及底层闭包调用**，**不等于模型自主选择工具、权限确认 UI 弹窗交互、后台自动回投至真实聊天窗口**。
> - 生产部署与单次短文本实测证明了特定显式路由（Aether + `z-ai/glm-5.3-flash`）通道通畅，**不等于保证底层 SDK 仅单次调用 HTTP、不声称对任意模型网关通用兼容、亦不替代双局域网段实机流转测试**。

### 3.3 跨语言端到端集成测试 (`tests/integration/`)

采用真实 Python HTTP 服务与 TypeScript 客户端在随机本地端口通信，依托 `EchoRunner` 模拟 Agent 回显（见 `tests/integration/README.md`）：

- **场景一（多格式流转）**：覆盖 1×1 像素 PNG（带标准 CRC）、UTF-8 文本、正规 xref 偏移量 PDF 及 ZIP 压缩包的真实字节双向传输，双向 SHA-256 校验一致。
- **场景二（状态恢复与重试）**：覆盖未收到服务端 202 确认时的进程重启恢复、相同 ID 幂等重新提交、409 冲突拦截及鉴权失败脱敏。
- **场景三（执行器故障隔离）**：覆盖 Companion 抛错后 Job 失败标记、错误信息脱敏及后续任务队列不受阻断继续执行。

### 3.4 真实 OpenCode 宿主加载与工具注册验证

在真实隔离的 OpenCode 宿主进程（版本 `2.0.24+de2cacd`）中执行专项冒烟验证，记录如下事实：

1. **插件入口解析与激活**：
   - **负控制**：配置指向仓库根目录时，宿主未加载该插件且枚举到的工具数为 0（由于宿主本地目录解析探测 `index.js`/`server.js`，而仓库根目录不含入口文件且会跳过单文件路径）；
   - **正控制**：配置指向编译输出目录 `/.../opencode-hermes-bridge/dist` 时，插件状态确认为 `active`，入口源为 `dist/index.js`，`features.server = true`。
2. **工具列表枚举**：

## 5. 已知工程限制与技术边界

1. **弱交付语义与重复可能**：任务在成功写入会话队列与本地 Outbox 标记为 `delivered` 之间若遭遇宿主异常退出，重启后可能导致重复投递通知。消费方需基于 Job ID 识别幂等性。
2. **网络访问控制与传输安全**：Companion 服务端仅支持 Bearer Token 基础鉴权，无内置 TLS 与抗 DDOS 能力。若需在受信任局域网（LAN）内提供服务，建议在容器 NetworkPolicy 与宿主机 ACL 两层实施双重源地址控制；上游 SNAT 可能掩盖真实来源，须核实服务器实际观察到的源地址（通用示例网段可参考 `192.168.1.0/24` 与 `192.168.10.0/24`），严禁直接暴露于公网；必须注意，局域网明文 HTTP 传输并非等同于 TLS（Bearer Token 与报文在内网链路仍为明文传输，并非绝对安全）；公网或不可信网络链路中强烈建议前置 TLS 反向代理或使用 VPN / 加密隧道。当前生产发布上线（production rollout）已完成，但真实客户端入站外部源地址身份仍为 **NOTPROVEN**，第二授权网段（示例 `192.168.10.0/24`）实机流转仍为 **NOTRUN**。
3. **模型可读格式边界**：仅图片与文本附件会被送入模型上下文；PDF、ZIP 等文件仅安全落盘并回显路径，不声称大模型能直接理解此类二进制文件。
4. **Outbox 存储膨胀**：当前 Outbox 数据持久化保留于宿主存储中，未内置定时自动清理策略，需注意会话长期使用的存储容量。
5. **显式模型路由范围与未实测边界**：显式路由接口模式当前版本仅支持 `chat_completions`。配置文档中的参数示例（如 `provider: custom`、网关基地址与模型名占位符）仅作为规范说明，不证明对任意第三方模型网关或未测试模型的绝对兼容性；虽已在 Aether 网关与 `z-ai/glm-5.3-flash` 模型上完成单次短文本实机冒烟（返回 `HERMES_BRIDGE_OK`），但该单次任务不代表底层 SDK 内部仅调用了一次 HTTP 请求，亦不代表对任意第三方模型网关或任意模型的通用兼容性；宿主交互式会话中的模型自主工具调用、权限弹窗及自动回投全链路 UI 未运行测试（插件端到端连接及宿主交互验证尚未完成）。
6. **容器 PID 1 守护入口实机验收与生产边界**：`hermes_bridge.init` 在同镜像真实容器 PID 1 环境下的进程形态、6 项 supervisor 契约、优雅终止及 Pod 删除已完成实机验收并全部 PASS。在生产 Kubernetes 部署中，此前卷根目录实测为 `02770`（`fsGroup` 上游存在放宽权限可能），修补后通过 init 容器使用固定目录文件描述符校验卷根目录并安全收紧为 `0700`（`10000:10000`），三个子目录沿用各自初始化检查，保证工作区全路径严格私有；编排层仍须保持 `hostPID: false`、`shareProcessNamespace: false` 并配置充足的终止宽限期（建议 30s）。当前测试覆盖了孤儿自然退出的回收，对脱离会话逃逸的后代仍依赖容器退出时内核清理 PID 命名空间；单次实测耗时受网络与 API 轮询影响，不作为固定性能 SLA 承诺。
