# OpenCode Hermes Bridge 验证与测试现状

本文档记录 OpenCode Hermes Bridge 各模块的测试覆盖证据、自动化验证结果、跨语言集成验证边界以及尚未完成的真实环境联调项。

- 适用项目：[OpenCode Hermes Bridge](https://github.com/zjm54321/opencode-hermes-bridge)
- 许可协议：GPL-3.0-or-later

---

## 1. 验证体系与分层边界

为了确保系统在网络不稳定、进程重启、恶意载荷及大文件传输下的健壮性，验证体系划分为五个层次：

1. **TypeScript 插件与客户端单元测试**：验证本地 Outbox 即时写入、配额前置校验、安全文件读取、轮询与退避机制、会话隔离及资源释放。
2. **Python Companion 服务端单元测试**：验证 HTTP 鉴权、单 Worker 串行执行、SQLite 崩溃恢复、幂等指纹计算、路径安全限制与凭证脱敏。
3. **跨语言端到端集成测试**：在本地真实 HTTP 协议栈下运行 TypeScript 核心客户端与 Python Companion 服务端，基于回显执行器（EchoRunner）验证多格式字节传输与生命周期完整性。
4. **真实 OpenCode 宿主加载与工具注册验证**：在真实 OpenCode 宿主环境下验证插件加载激活、工具清单枚举、闭包执行降级与零未授权连接。
5. **真实环境模型交互与外部 Hermes 最小联调**：验证通过真实 Hermes Runner 与 AIAgent 链路执行真实模型调用与文件运输，严格区分文本成功、夹具文件传输成功与未决的视觉理解及 UI 回投。

> **重要边界声明**：
> - 自动化跨语言测试采用标准回显桩（EchoRunner）测试真实网络与文件字节流动，**不等于真实 Hermes 模型的语义理解**。
> - 真实宿主加载验证证明了插件在宿主内的**加载激活、工具注册及底层闭包调用**，**不等于模型自主选择工具、权限确认 UI 弹窗交互、后台自动回投至真实聊天窗口，亦不等于与真实 Hermes 建立了端到端通信**。

### 3.3 跨语言端到端集成测试 (`tests/integration/`)

采用真实 Python HTTP 服务与 TypeScript 客户端在随机本地端口通信，依托 `EchoRunner` 模拟 Agent 回显（见 `tests/integration/README.md`）：

- **场景一（多格式流转）**：覆盖 1×1 像素 PNG（带标准 CRC）、UTF-8 文本、正规 xref 偏移量 PDF 及 ZIP 压缩包的真实字节双向传输，双向 SHA-256 校验一致。
- **场景二（状态恢复与重试）**：覆盖未收到服务端 202 确认时的进程重启恢复、相同 ID 幂等重新提交、409 冲突拦截及鉴权失败脱敏。
- **场景三（执行器故障隔离）**：覆盖 Companion 抛错后 Job 失败标记、错误信息脱敏及后续任务队列不受阻断继续执行。

### 3.4 真实 OpenCode 宿主加载与工具注册验证

在真实隔离的 OpenCode 宿主进程（版本 `2.0.24+de2cacd`）中执行专项冒烟验证，记录如下事实：

1. **插件入口解析与激活**：
   - **负控制**：配置指向仓库根目录时，宿主未加载该插件且枚举到的工具数为 0（由于宿主本地目录解析探测 `index.js`/`server.js`，而仓库根目录不含入口文件且会跳过单文件路径）；
   - **正控制**：配置指向编译输出目录 `/.../opencode-hermes-bridge/dist` 时，插件状态确认为 `active`，入口源为 `dist/index.js`，`features.server = true`。
2. **工具列表枚举**：
   - 宿主 `ctx.tool.list()` 正确枚举出 `hermes_ask`、`hermes_status`、`hermes_resume` 三个工具及其完整 Schema 与权限配置。
3. **闭包执行与安全降级**：
   - **无 Token 情况**：直接调用三个工具执行器，均正确触发安全降级响应（提示配置 Bearer Token，且确认未向配置的测试端点发起 HTTP 请求）；
   - **提供测试 Token 情况**：调用 `hermes_status` 成功返回 `[]`，证实 Bridge 实例与底层 storage 初始化正常运作。
4. **测试端点连接观察**：
   - 本地端口监听在激活运行超过 2 个轮询周期（5 秒以上）内观测到针对测试端点的 **0 次连接**，且未向真实 Hermes 发送请求；
   - 验证所启动的 6 个隔离宿主进程在测试结束后均已通过 SIGTERM 正常退出，未对用户持久服务造成任何影响。

## 4. 真实外部实体与模型联调现状

在受控隔离环境下，针对真实 Hermes（版本 `0.21.5`）及真实 OpenCode 宿主执行了最小化联调（注：本节记录基于此前版本默认调用链路的历史联调证据，**不包含亦不证明本次新增显式模型路由的实机调用**；新增路由尚未进行真实网关验证），测试结果与分层结论如下：

### 4.1 最小文本调用与基础交互 (text: PASS)

- **调用链路**：在完全隔离的临时环境（独立 HOME、独立测试线程）中，经项目核心链路 `JobService -> HermesRunner -> run_agent.AIAgent` 执行；
- **执行结果**：向真实模型发起 1 次 HTTP 调用并成功返回 200，Hermes 报告 `completed=true`，返回预期的固定回复文本 `HERMES_BRIDGE_SMOKE_OK`；
- **副作用隔离**：单次调用中工具调用数为 0，fallback 激活数为 0；显式跳过了长期记忆持久化、用户 Profile 加载、会话数据库及后台审阅流程，未对已有生产部署或业务状态造成任何修改。

### 4.2 夹具文件字节双向运输 (fixture file transport: PASS)

- **落盘与运输比对**：输入的测试 TXT 文件与 1×1 像素有效 PNG 文件经 Companion 输入正确写入工作区；测试生成的远端输出文件经序列化传输并在本地回收后，双向 SHA-256 哈希值完全一致（验证了文件描述符读取、规范 Base64 编码、物理文件写入及哈希保真）；
- **特别说明**：
  1. 输出文件的字节内容由测试夹具生成，**不是由 Hermes 模型自主创建**；
  2. TXT 文件的内部内容未交由大模型读取；
  3. 本项测试仅覆盖真实 Hermes Runner / JobService 链与文件运输机制，不包含完整的浏览器/前端 UI 链路。

### 4.3 模型图片视觉理解 (model image understanding: INCONCLUSIVE)

- **测试现象**：Companion 在构建输入时正确包含了 `image_url`，但 Hermes 0.21.5 在准备底层模型请求时移除了图像片段（image parts）。安全校验 Guard 在请求发送前拦截阻断，因此**没有任何图像数据被送达上游模型**；
- **结论定性**：因图像未送达上游，**无法判定上游模型是否具备视觉理解能力**。隔离的临时 HOME 未配置视觉能力覆盖项且模型元数据探测被禁用，此结果反映的是特定测试环境配置约束而非模型不支持；
- **资源清理**：图像任务在 120 秒未取得终止状态后，监管进程终止了自建进程组，并完整清理了所有自建目录与相关进程，未追加额外模型调用。

### 4.4 真实宿主 UI 与权限交互 (full UI: NOT RUN)

- **当前状态**：未运行。虽然第 3.4 节已证实插件能被真实 OpenCode 宿主加载、枚举工具并直接执行闭包，但尚未在宿主交互式会话中测试大模型自主决策调用工具、前端权限弹窗确认流程以及 `ctx.session.prompt` 向真实聊天界面的异步渲染与回投。

### 4.5 状态分层汇总

| 验证维度 | 测试状态 | 说明 |

| **真实文字指令回复** | **PASS** | 1 次真实模型 HTTP 200 调用，成功获取固定文本回复 |

## 5. 已知工程限制与技术边界

1. **弱交付语义与重复可能**：任务在成功写入会话队列与本地 Outbox 标记为 `delivered` 之间若遭遇宿主异常退出，重启后可能导致重复投递通知。消费方需基于 Job ID 识别幂等性。
2. **网络访问控制与传输安全**：Companion 服务端仅支持 Bearer Token 基础鉴权，无内置 TLS 与抗 DDOS 能力。若在受信任局域网（LAN）内使用 HTTP 访问，必须实施内网源地址访问控制并禁止向公网暴露；必须注意，局域网明文 HTTP 传输并非等同于 TLS（Bearer Token 与报文在内网链路仍为明文传输，并非绝对安全）；公网或不可信网络链路中强烈建议前置 TLS 反向代理或使用 VPN / 加密隧道。
3. **模型可读格式边界**：仅图片与文本附件会被送入模型上下文；PDF、ZIP 等文件仅安全落盘并回显路径，不声称大模型能直接理解此类二进制文件。
4. **Outbox 存储膨胀**：当前 Outbox 数据持久化保留于宿主存储中，未内置定时自动清理策略，需注意会话长期使用的存储容量。
5. **显式模型路由范围与未实测边界**：显式路由接口模式当前版本仅支持 `chat_completions`。配置文档中的参数示例（如 `provider: custom`、网关基地址与模型名占位符）仅作为规范说明，不证明对任意第三方模型网关或未测试模型的绝对兼容性；该功能目前仅通过 Python 单元测试（25 项）完成参数注入、格式校验与指定测试场景下的脱敏验证，新增路由尚未进行真实网关验证，亦未完成新环境部署。
